{{ "Permissions"|t }}

{{ "Every upload carries three independent permissions: read, write and list. Unlike the older fixed privacy levels, each one is granted on its own, so you can combine them freely. Each permission answers exactly one question: read — who can see the content; write — who can modify or remove it; list — whether it shows up in the public list."|t }}

{{ "Read permission"|t }}
  • allow — {{ "anyone who knows the identifier can view the content. No password is needed."|t }}
  • password — {{ "a read password is required. The text content and all attachments are stored encrypted on the server with that password, so nobody can read them without it, not even from a copy of the database."|t }}

{{ "Scope: the upload page (/upload/...), the raw text view (/raw/...), single file downloads (/file/...), the zip download (/archive/...), the URL short link (/url/... and /u/...) and the editor — you must be able to read the content before you can edit it."|t }}

{{ "Write permission"|t }}
  • allow — {{ "anyone who knows the identifier can edit the content and remove the upload."|t }}
  • password — {{ "a write password is required to edit or remove the upload. This password only decides whether you are allowed to write; it is never used to encrypt anything."|t }}
  • refuse — {{ "writing is refused altogether. Nobody can edit or remove the upload. The server administrator can still remove it with the administrator password."|t }}

{{ "Scope: saving an edit (/edit/...), removing an upload (/remove/...), and whether the edit and remove links are shown at all. Note that editing needs both permissions: read to see the current content and write to save it."|t }}

{{ "List permission"|t }}
  • yes — {{ "the upload is listed on the public /list page."|t }}
  • no — {{ "the upload is not listed, but it is still reachable by anyone who knows its identifier, subject to the read permission."|t }}

{{ "Scope: only the public /list page. The edit and remove links on that page are still governed by the write permission."|t }}

{{ "How passwords are verified"|t }}

{{ "Passwords are never stored. When an upload is created, the server derives a verification value from the upload identifier and the password you typed, and stores only that value. To check a password later it decrypts the stored value with the submitted password: the check passes when the result is exactly the identifier of that upload."|t }}

{{ "This has two advantages: it works even when the text content is empty, which happens whenever an upload only carries attachments; and the cost of checking does not depend on how large the content is."|t }}

{{ "The read password has a second job: when read is set to password, the text content and the attachments are encrypted with it, so the same password both passes the check and unlocks the content. The write password has no such second job — it is purely an authorisation check and never encrypts anything. The two passwords are independent and may be the same or different."|t }}

{{ "The server keeps neither the plaintext password nor the plaintext content. If you forget a read password, the content it protects cannot be recovered."|t }}

{{ "Recommended combinations"|t }}

{{ "Because the three permissions are independent, the same effect as an old privacy level is just one particular combination. A few common ones:"|t }}

{{ "What you want"|t }} read write list
{{ "A fully public pasteboard"|t }} allow allow yes
{{ "Share by link, but keep it out of the list"|t }} allow allow no
{{ "Read-only share: anyone with the link may look, nobody may change"|t }} allow refuse no
{{ "Anyone may read, only the password holder may change"|t }} allow password no
{{ "Private: both reading and writing need a password"|t }} password password no
{{ "Private and locked: readable with a password, never writable"|t }} password refuse no
{{ "Listed but still private: the list shows the link, the content still needs the password"|t }} password password yes
